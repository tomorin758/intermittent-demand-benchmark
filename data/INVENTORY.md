### 2.3 Schema fragmentation (three per-series schemas, two JSON schemas)

`*_per_series.csv` files come in **three mutually incompatible column layouts**:

1. `series,mae,rmse,bias,mase,rmsse,zero_precision,zero_recall,zero_f1,seg_rmse_zero,seg_rmse_one,seg_rmse_ge2`
   → Croston / SBA / TSB (all datasets).
2. `series,MAE,RMSE,MAE_nonzero,RMSE_nonzero,QL(0.5),0Precision,0Recall,0F1`
   → DeepAR / DeepAR-negbin / LSTM / TCN / WaveNet (all datasets).
3. `series,mae_non_zero,rmse,ql,zero_precision,zero_recall,zero_f1,seg_rmse_zero,seg_rmse_one,seg_rmse_ge2`
   → DLinear (`intermittent_results/*_DLinear_per_series.csv`).

Only schema 2 carries `QL(0.5)`; none of the three carries the truncation flag `c`, the
six quantile-segment columns, or the four ADI–CV² class columns used in the paper tables.

`*_overall.json` comes in **two schemas**:

* new 16-metric schema (`QL(0.5)`, `NT_*`, `QL(0.5,c=0.5)`, `T_*`) — 48 of 57 files;
* old schema (`mae, rmse, bias, mase, rmsse, zero_precision, zero_recall, zero_f1,
  seg_rmse_zero, seg_rmse_one, seg_rmse_ge2`) — **9 files**, exactly the classical-method
  subset runs:
  `croston_results/{m5_top200,m5_top1000,fresh_retail_top200}_croston_overall.json`,
  `intermittent_results/{m5_top200,m5_top1000,fresh_retail_top200}_{sba,tsb}_overall.json`.
  These files therefore cannot reproduce the paper's truncated/zero-aware columns.

### 2.4 Two zero-classification conventions coexist in the same module

`PatchTST_supervised/utils/metrics.py` contains both the current functions (strict `< c`,
`_zero_classification`, lines 184–201) and legacy functions that will disagree with them:

* `zero_metrics` (lines 65–86) uses `true <= threshold` / `pred <= threshold`;
* `segment_rmse` (lines 88–111) uses three demand bins (`<=c`, `c<x<2`, `>=2`), not the
  six non-zero quantile segments used in the paper.

Anything computed through the legacy path is **not** comparable with the paper's tables.

## 4. Metric implementation

Four independent implementations of the protocol exist. They agree on the definitions but
differ in naming, so **the paper's numbers are only reproducible with the implementation that
produced the specific artifact**.

### 4.1 QL(0.5) — pinball loss at τ = 0.5

`PatchTST/PatchTST_supervised/utils/metrics.py:156-161`:

```python
def _ql(pred, true, rho=0.5):
    """Internal: quantile loss over the flattened arrays."""
    p = np.asarray(pred, dtype=np.float64).ravel()
    t = np.asarray(true, dtype=np.float64).ravel()
    e = t - p
    return float(np.mean(np.where(e >= 0, rho * e, (rho - 1) * e)))
```

`PatchTST/PatchTST_supervised/eval_metrics.py:35-45`:

```python
def quantile_loss(pred, true, rho=0.5):
    """
    QL(rho) = 1/N * Σ ρ_rho(y - ŷ)
    With rho=0.5, QL(0.5) = 0.5 * MAE
    """
    ...
    loss = np.where(e >= 0, rho * e, (rho - 1) * e)
    return float(np.mean(loss))
```

`PatchMixer/eval_metrics.py:122-123` and `granite-tsfm/eval_metrics.py:122-123`
(the two files are byte-identical, md5 `1f55b7ddf127fd0306ecdfa9bcdc0296`):

```python
    # 1.1 QL(0.5) = 0.5 * MAE
    results['QL(0.5)'] = 0.5 * np.mean(np.abs(p - t))
```

`TweedieGP/src/eval_metrics.py:96-98`:

```python
    # ── 1. QL(0.5) = 0.5 * MAE ──
    mae = np.mean(np.abs(y_flat - yh_flat))
    results['QL(0.5)'] = 0.5 * mae
```

So QL(0.5) ≡ 0.5 × MAE in every implementation, as the PatchTST project notes also state
(`QL(0.5) = 0.5 × MAE`). The paper's `main.tex:7` question is therefore answered: **yes**,
QL(0.5) is exactly 0.5·MAE.

**But the `MAE`/`RMSE` columns of the result tables are the non-zero variants, not the

```python
def _truncate(values, c):
```

### 4.3 Zero precision / recall / F1

Current definition — **strict inequality, positive class = “actual < c”**, computed on the
**untruncated** arrays even in the truncated metric block:

`PatchTST/PatchTST_supervised/utils/metrics.py:184-201`:

```python
def _zero_classification(pred, true, c=0.5):
    """
    0Precision / 0Recall / 0F1
    Positive class = "actual value < c" (treated as no demand)
    TP0: actual < c and predicted < c
    FP0: actual >= c and predicted < c
    FN0: actual < c and predicted >= c
    """
    ...
    tp = np.sum((t < c) & (p < c))
    fp = np.sum((t >= c) & (p < c))
    fn = np.sum((t < c) & (p >= c))
    eps = 1e-12
    precision = tp / (tp + fp + eps)
    recall = tp / (tp + fn + eps)
    f1 = 2 * precision * recall / (precision + recall + eps)
```

and the call site `metrics.py:365` (note the arguments are the **untruncated** `pf`, `tf`):


its call site `:327-329` likewise passes `pred_flat, true_flat` (untruncated).

### 4.5 ADI–CV² demand-regime classification

Thresholds are the Syntetos–Boylan values **1.32 (ADI)** and **0.49 (CV²)**, identical in all
four implementations, and are always computed on the **training-history window only**.

`PatchTST/PatchTST_supervised/utils/metrics.py:260-285`:

```python
def _adi_cv2(hist_series, c=None):
    """One history series -> (ADI, CV^2)."""
    h = np.asarray(hist_series, dtype=np.float64)
    if c is not None:
        h = h.copy()
        h[h < c] = 0.0
    T = len(h)
    nz = np.sum(h > 0)
    if nz == 0:
        return np.inf, np.inf
    ADI = T / nz
    nz_vals = h[h > 0]
    eps = 1e-12
    CV2 = (np.std(nz_vals) / (np.mean(nz_vals) + eps)) ** 2
    return float(ADI), float(CV2)

def _classify(ADI, CV2):
    if ADI < 1.32 and CV2 < 0.49:
        return "Smooth"
    elif ADI >= 1.32 and CV2 < 0.49:
        return "Intermittent"
    elif ADI < 1.32 and CV2 >= 0.49:
        return "Erratic"
    else:
        return "Lumpy"
```

## Appendix B — collection rules and classification decisions

**Copy rules applied** (in this order):

1. A file is copied only if it is **< 20 000 000 bytes** (20 MB decimal). 1 106 artifacts fail
   this and exist in the manifest only.
2. `.pt`, `.pth`, `.ckpt`, `.bin`, `.safetensors`, images, `.pdf`, notebooks and all source code
   are never listed or copied.
3. `x.npy` (PatchMixer) and `hist.npy`/`*_hist.npy` (PatchMixer, granite) are **model input
   tensors derived from the datasets**, so they are neither listed nor copied — per the
   “do not list … the datasets themselves” rule. The same applies to
   `granite-tsfm/results/*/chunks/*.csv` (input data chunks), `PatchTST/m5/*.csv`,
   `*/dataset/*.csv`, `TweedieGP/data/**` and `GA/**/pts/dataset/**`.
4. Redundant shards are not copied: a `*_chunk_*.npy` whose directory also contains the merged
   `pred.npy`/`true.npy`/`merged_preds.npy`, or any chunk shard > 2 MB (those sets run to
   2.4 GB per run). 366 artifacts were dropped this way; their metrics files are kept.
5. **Content deduplication**: files are hashed (md5) and identical content is copied once.
   94 files in 40 content groups were dropped, e.g. the identical `true.npy` shared by all
   models evaluated on the same dataset/window — for `fresh_retail` the surviving copy is
   `data/evidence/fresh_retail/DLinear/fresh_retail_28_7_DLinear_custom_ftM_sl28_ll14_pl7_dm512_nh8_el2_dl1_df2048_fc1_ebtimeF_dtTrue_Exp_0__true.npy`,
   which every model on that dataset can be scored against. Cross-references are recorded in
   `/tmp/dupskipped.tsv` at generation time; the manifest still lists every source file.
6. Symlinked artifact directories (`PatchTST_supervised/analysis/output/moirai_parts_ft` and
   `…/moirai_zs_m5`, both pointing into `<workspace>/data/PatchTST_artifacts/`) were resolved and
   the real files collected from the artifact root.
